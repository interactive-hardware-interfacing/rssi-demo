Hardware

Two boards, one button, and nothing between them but air.

Two roles

Bridge (receiver)XIAO ESP32-C3 running the bridge firmwareu.FL antennaLaptop USB-C
TX (sender)XIAO ESP32-C3 running the TX firmwareu.FL antenna, pushbutton on D1USB bank

Identical boards; the Firmware tab decides which is which. Give the sender a little enclosure or handle so a volunteer can carry it without touching the antenna.

Parts

  • 2× Seeed XIAO ESP32-C3 with the u.FL antenna that ships with it.
  • One momentary pushbutton (any tactile switch) for the TX board.
  • USB-C data cable for the bridge (not charge-only), and a USB power bank with a second cable for the sender.
  • Tape for floor marks, and a tape measure.

Things that bite

  • A loose u.FL connector shows up as LINK LOST — check it first.
  • The XIAO’s antenna is directional-ish; how a volunteer holds the board changes RSSI. Fun to demo, worth knowing.
  • Both boards pin Wi-Fi channel 6; keep them matched.
  • If the chooser shows no port, the cable is the usual suspect — many USB-C cables are charge-only.
  • A board that won’t take firmware: hold BOOT (B), tap RESET (R), release BOOT, then try again.

Pinout detail is in wiring/wiring.md.

Put the firmware on the boards

Two roles, bridge and TX, each a single code.py written straight from this page. Chrome or Edge.

1. Plug in

Connect one XIAO ESP32-C3 over USB. If the instrument is connected to a board, this page disconnects it first.

2. Pick its job

Install bridge for the board that will stay at the laptop and receive. Install TX for the board that gets the button and walks away. Pick the port named USB JTAG/serial debug unit.

3. Wait for the first line

The page writes code.py over CircuitPython’s REPL, checks its size and CRC on the board, reboots it, and waits for the firmware to announce itself. Then do the other board.

4. Connect

Back on the instrument, click Connect bridge and pick the bridge’s port. Power the TX board from a bank and the gauges come alive.

Ready. Plug a board in and pick its role.
No CircuitPython on that board. A XIAO ESP32-C3 fresh from the bag runs Seeed’s factory sketch, not CircuitPython. Install CircuitPython once with the button below, then come back to Install bridge or Install TX.

About this demo

What it shows, how to run it in front of a room, and where the numbers come from.

What it shows

A radio link doesn’t just get “quieter” with distance — it works, then falls off a cliff. One board sends steadily; the other, plugged into the laptop, measures how strong each packet arrives (RSSI, in dBm) and how many go missing. Walk the sender away and you can watch the signal fade smoothly while delivery holds… until it suddenly doesn’t.

Try this during the tour: start close, press Mark distance, then walk to each taped mark and mark again. The bar chart fills in. Press the button on the sender to drop the transmit power and watch the whole curve shift in.

How it works

TX sends 10 sequenced packets/sec → the bridge reports each one’s RSSI and counts sequence gaps as loss → this page averages a sliding window for the gauges and bins it by the distance you mark. Pressing the sender’s button sets wifi.radio.tx_power; the firmware reads back the actual value the radio accepted and puts it in the packet, so the TX-power readout is real, not what we asked for. The line format is in PROTOCOL.md.

Known quirks:

  • RSSI is noisy — that’s real, not a bug. The sliding-window average smooths it for the gauges.
  • The simulator’s Step power button stands in for the real button on the TX board; with hardware, press the board’s button.
  • LINK LOST means no packet for about a second; it clears on the next one.
