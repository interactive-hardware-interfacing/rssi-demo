About this demo

What it shows

A radio link doesn’t just get “quieter” with distance — it works, then falls off a cliff. One board sends steadily; the other, plugged into the laptop, measures how strong each packet arrives (RSSI, in dBm) and how many go missing. Walk the sender away and you can watch the signal fade smoothly while delivery holds… until it suddenly doesn’t.

Try this during the tour: start close, press Mark distance, then walk to each taped mark and mark again. The bar chart fills in. Press the button on the sender to drop the transmit power and watch the whole curve shift in.

How it works

TX sends 10 sequenced packets/sec → the bridge reports each one’s RSSI and counts sequence gaps as loss → this page averages a sliding window for the gauges and bins it by the distance you mark. Pressing the sender’s button sets wifi.radio.tx_power; the firmware reads back the actual value the radio accepted and puts it in the packet, so the TX-power readout is real, not what we asked for. Same bridge serial format as the rest of the family (see PROTOCOL.md).

Known quirks:

  • RSSI is noisy — that’s real, not a bug. The sliding-window average smooths it for the gauges.
  • The XIAO’s u.FL antenna is directional-ish; how you hold the board changes RSSI. Fun to demo, worth knowing.
  • If the antenna is loose you’ll see LINK LOST. Check the u.FL first.
  • Both boards pin channel 6; keep them matched.
  • Flashing stuck? Hold BOOT, tap RESET, release BOOT.

Put the firmware on the boards

One-time step per board. Both run CircuitPython; you copy a code.py onto each.

  1. Install CircuitPython on each XIAO ESP32-C3 if needed (board page).
  2. Bridge board: copy firmware/bridge/code.py. Plug this one into the laptop.
  3. TX board: copy firmware/tx/code.py, wire a pushbutton from D1 to GND, power from a USB bank.
  4. Connect. Click Connect bridge and pick the USB JTAG/serial port.

Identical hardware except the TX board’s button. Label them, keep pre-flashed spares.
